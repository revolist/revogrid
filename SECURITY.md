# Security Policy

This policy covers the open-source RevoGrid core (`@revolist/revogrid`) and source code maintained in this repository. For commercial plugins and the Pro portal, see the [RevoGrid Pro security policy](https://github.com/revolist/revogrid-pro/blob/main/SECURITY.md).

## Supported versions

Security fixes target the latest stable minor release line. Older minor and major versions receive fixes on a best-effort basis; upgrade to the latest stable release to receive security updates. Fixes may be published as patch releases, with mitigation guidance where available.

## Report a vulnerability privately

Email [info@rv-grid.com](mailto:info@rv-grid.com). If GitHub private vulnerability reporting is enabled for this repository, you may also use **Security → Advisories → Report a vulnerability**.

Do not report suspected vulnerabilities through public issues, discussions, or pull requests. Include:

- Affected package, component, and version range.
- Potential impact and the conditions needed to exploit the issue.
- Reproduction steps, a minimal sample, or a proof of concept.
- Browser, operating system, and relevant configuration.
- Any known workaround or suggested mitigation.

Remove credentials, personal information, and customer data from reproductions. If you are unsure whether an issue is security-related, use the private email channel first. Ordinary bugs can be reported through [GitHub Issues](https://github.com/revolist/revogrid/issues).

## Response and coordinated disclosure

Vulnerability reports for the open-source RevoGrid core are reviewed on a best-effort basis, without guaranteed response or remediation times. Maintainers will provide updates as the investigation progresses.

The **2-business-day acknowledgement commitment** applies to RevoGrid Pro. See the [RevoGrid Pro security policy](https://github.com/revolist/revogrid-pro/blob/main/SECURITY.md) and [published security policy](https://rv-grid.com/pro/policies/security) for Pro response commitments and remediation targets.

Please coordinate disclosure with the maintainers and allow time for a fix to be released before publishing vulnerability details. Security fixes and affected versions are communicated in release notes; a GitHub Security Advisory may also be published. You can follow [RevoGrid releases](https://github.com/revolist/revogrid/releases) for updates.

## Responsible research

Make a good-faith effort to avoid privacy violations, data loss, and service disruption. Test with systems and data you own or are authorized to assess, and collect only what is necessary to demonstrate the issue. Let us know whether and how you would like to be credited when the issue is disclosed.

For the broader secure development and supplier assessment policy, see [RevoGrid Security Policy](https://rv-grid.com/pro/policies/security).
